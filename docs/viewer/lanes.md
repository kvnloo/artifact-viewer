# Lanes

A lane is one product's pieces. The names come from the projects named in the brief and from the filesystem pass.

| Lane | What shows up there |
| --- | --- |
| `starwars` | Kanban board stills and pages |
| `pokemon/cardtwin` | Card stills, webm HITL clips |
| `kanto` | The broader Pokémon set the brief named next to cardtwin |
| `charizard` | Character reviews and turnarounds under `pokemon-iac` |
| `pokedex` | Device PWA builds and review batches |
| `temple-guard` | Humanoid and weapon bakeoffs |
| `homebase-pickleball` | Facility stills, Blender heroes |
| `helio-cortex` | The other workstream Telegram asked to see beside Homebase |
| `growtwin` | Dream-loop captures, refs, GLBs, `JUDGE_*.md` |
| `wizard-chess` | The build that had to stay distinguishable from cleanup |
| `spatial-canvas` | Desktop previews |
| `hermes-liquid-glass` | UI stills |
| `zer0-company` | Site comps and motion |

Two lanes stay separate. Telegram asked to keep seeing both workstreams, not a single mixed grid.

This page does not pull those disks into the public site. A fork adds artifacts with [embeds](/viewer/embed) inside the lane's doc.
